# Restaurant Full Curriculum Map

## Purpose

This document defines the full first-pass curriculum map for the `Restaurant` category.

The key design change is:

- one learner-facing subject like `Food Words` is not enough by itself
- each subcategory needs multiple internal lesson levels
- each internal lesson level should contain roughly `15-25` questions
- each lesson should introduce a little new material while reviewing previous material

This is the structure that makes the curriculum actually scalable.

## Final Hierarchy

For the restaurant branch, the hierarchy should be:

1. `City`
2. `Category`
3. `Subcategory`
4. `Level`
5. `Component`

Example:

- `Tokyo`
- `Restaurant`
- `Food Words`
- `Level 3: Casual Menu Items`
- `Recognition / Matching / Review`

## Curriculum Goals

The restaurant category should eventually allow the learner to:

- recognize common food and drink words
- understand how menus are grouped
- read simple menu items and prices
- ask what something is
- ask what is recommended
- place a polite simple order
- order drinks and set meals
- answer very common server questions
- make simple modifications
- ask for extra items
- ask for the check
- handle a basic payment exchange
- leave naturally

The learner does not need to sound advanced.

The learner does need enough repeated exposure that restaurant Japanese becomes familiar rather than intimidating.

## Restaurant Survival Content Checklist

If this branch is doing its job, the learner should eventually be able to handle all of these moments:

- recognize common foods, drinks, desserts, and sushi items
- understand menu section headings instead of treating menus like random symbols
- read a real menu with prices, categories, and a few recommended items
- get the server's attention politely with `すみません`
- ask what something is when a menu item is unfamiliar
- ask what is recommended
- point and order one item
- order by naming the item directly
- order drinks naturally
- understand basic server prompts like `Have you decided?`
- answer very simple follow-ups
- request water, the menu, napkins, a spoon, or another item
- handle simple modification language like `no onion` or `no wasabi`
- recognize common condiments and table items
- order dessert or an after-meal drink
- ask for the check
- handle cash-or-card language
- leave naturally with the right thank-you phrase

If a learner finishes the branch and still does not feel more ready to order in Japan, the branch is too shallow.

## Category Structure

`Restaurant` should be broken into the following subcategories.

- build a broad usable vocabulary base before ordering

1. `Drinks and Staples`
2. `Proteins and Sides`
3. `Casual Menu Items`

## Sequencing Recommendation

The strongest beginner route is:

1. `Food Words`
2. `Menu Categories`
3. `Reading a Simple Menu`
4. `Asking What Something Is`
5. `Ordering One Item`
6. `Ordering Drinks`
7. `Ordering Meals and Set Meals`
8. `Getting the Server's Attention`
9. `Understanding the Server`
10. `Preferences and Modifications`
11. `Extra Requests`
12. `Food Descriptions and Preferences`
13. `Condiments and Table Items`
14. `Dessert and Cafe Flow`
15. `Paying and Finishing`

`Quantities and Same-As-That` can branch slightly later rather than blocking everything.

## Why This Is Better

This structure solves the real problem the prototype exposed:

- one `Food Words` lesson was far too small
- the app needs repeated cycles of introduction, recognition, meaning, guided recall, and review
- restaurant survival depends on many nouns, many category headings, and several reusable phrase frames

This map gives the branch enough room to become genuinely useful.
